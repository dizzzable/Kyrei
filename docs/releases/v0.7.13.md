# Kyrei v0.7.13 — 🔭 the Memory Atlas actually renders

The 3D Memory Atlas shipped in v0.7.11 drew a black rectangle. This release
fixes it, and the diagnosis is worth recording: reading the code produced two
confident, wrong explanations. The answer only arrived by attaching a debugger
to the running app and measuring — the renderer sat on frame 1 with **zero draw
calls**, while the scene held 3 398 meshes and one manual `render()` produced
3 398 draw calls immediately.

## 🖤 Why it was black

Two separate failures, one root cause: the view depended on browser callbacks
that only fire while a window is producing frames.

- **The render loop could stall forever.** `requestAnimationFrame` does not run
  while a document is hidden, minimised or occluded. If the Atlas mounted then,
  the graph library's internal "running" flag stayed set while no frame was ever
  queued — and `resumeAnimation()` early-returns on that flag, so it never
  recovered. No tick meant no position sync either: every node object sat at the
  origin while its coordinates waited in the data.
- **The graph could fail to be created at all.** `ResizeObserver` delivery is
  also part of the rendering lifecycle, so the container size never arrived and
  the canvas was never mounted. Measured live: a container of 868×685 with zero
  canvases.

Both are fixed — the size is now read directly at mount, and a stalled loop is
restarted on mount and whenever the window becomes visible.

## 🎨 Colour

- **886 of 1 898 nodes were pure black.** `THREE.Color` cannot parse
  `color-mix()`, `oklch()` or the modern slash-alpha `rgb()` syntax; given one it
  warns and leaves the colour at its default, which is black. Three of the
  theme's tokens are `color-mix()`. Colours are now normalized through the
  browser before they reach three.js.
- **Ten node kinds rendered as four colours**, five of them identical, because
  the theme's semantic tokens collapse — `primary` and `success` are the same
  teal; `muted`, `secondary` and `faint` are the same base. The Atlas now has its
  own palette, grouped so the graph reads by family: cool blues for the project's
  own material, warm tones for work in progress, violets for what the agent
  remembers.
- **Edges are colour-coded by type**, so a link says what kind of connection it
  is — containment, an import, a reference, or semantic similarity — instead of
  two near-identical greys.

## 📐 Framing and scale

- The camera now frames the graph once the layout settles. Nothing did before:
  the code said "the component does not auto-fit", and a selection could not
  cover for it because that path bails when a node has no coordinates yet —
  exactly the case on first render.
- Node size is read against the layout's scale. A graph of this size spreads
  across ~2 600 world units, where the library's default radius is under a pixel
  once the whole thing is in frame — drawn perfectly, and invisible.

## 🧹 Also

- `react-force-graph-3d` moved from `devDependencies` to `dependencies`, where a
  runtime UI library belongs.
- The WebGL teardown effect had `[size.width, size.height]` as its dependencies
  under a comment saying "on unmount". React runs a cleanup on every dependency
  change, so it destroyed the renderer of a still-mounted graph on the first
  resize.
- Renderer components are now tested by rendering them: `jsdom` and Testing
  Library replaced a test that matched regexes against source text, a form that
  breaks on a rename and passes on dead code.
