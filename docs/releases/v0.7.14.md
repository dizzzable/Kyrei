# Kyrei v0.7.14 — 🗺️ the Atlas becomes a map, and the agent sees the imports it was blind to

v0.7.13 made the Memory Atlas render. This release makes it *legible* — and
along the way it fixes something more important than any picture: the agent's
own model of the project was missing an entire layer of dependencies.

Everything below was measured against the running app with a debugger attached,
not inferred from reading the code. Three of these bugs were invisible to
reading and obvious to measurement.

## 🔌 The agent could not see 11% of its own imports

`project_impact` — "who breaks if I edit this file" — walks the extracted
import graph. That extractor only accepted specifiers beginning with `.`, so
every alias import was discarded. On this repository that is **880 of 8 306
internal imports**, and they are not spread evenly: they are concentrated in
`src/`, which meant the agent's picture of the renderer was very nearly empty.

- **Aliases are now resolved** from `compilerOptions.paths`, `tsconfig.json`
  first and `jsconfig.json` after it, honouring `baseUrl` and preferring the
  longest matching prefix. Import edges on this repository went **290 → 776**,
  with `src/` going from almost nothing to **611**.
- **The config parser handles JSONC.** `tsconfig.json` is JSONC by convention,
  so a plain `JSON.parse` fails on most real projects — silently leaving every
  alias unresolved. It is scanned character by character rather than by regex,
  because a naive one mangles any string containing `//`.
- Build-tool aliases (Vite, webpack) are deliberately **not** evaluated. This
  index stays offline and deterministic; it does not execute workspace config.

### 🧊 …and the fix would have been invisible

The incremental index caches edges keyed by **file content hash**. Nothing
invalidated that when the *meaning* of the content changed: editing
`tsconfig.json` paths, or shipping a smarter extractor, left every untouched
file holding the edges the old rules produced — indefinitely. Alias support
would not have appeared on any existing workspace until each file happened to
be edited.

The index now stores an extractor signature (logic version + a hash of the
alias table). If either changes, everything is re-parsed.

## 🧭 A quarter of the graph had no edges at all

The Atlas graph and the sidebar tree were two independent models. The tree knew
about directories; the graph did not. A code file was connected only if it was
one of ≤40 entry candidates or the target of an import — so **426 of 696 files
had no edge whatsoever**, and rendered as unattached dots.

Containment is now **derived from the tree**, so the graph *is* the tree plus
its semantic overlays. Every directory is a node, every node has a path back to
the workspace root, and every chat session gets its own folder.

**Isolated nodes: 445 → 0.**

## 🧪 `related` was zero by arithmetic, not by design

The semantic-similarity layer was written, wired and enabled — and its budget
was computed as *whatever the structural edges left over*. The structural edges
alone came to 1 519 against a limit of 1 500, so the reserve evaluated to
exactly **zero** and the similarity pass never ran once. Nineteen structural
edges were being dropped in silence on top of that.

The budget is now spent in strict priority order — skeleton, then overlays, then
a reserved slice for similarity taken only from room the skeleton did not need
— and anything dropped is reported instead of vanishing. Live graph: **354
`related` edges** where there were none.

## 🧱 Directories look like directories

- **Folders are octahedrons, files are spheres.** Colour could not carry this:
  a folder is drawn in its region's hue and so is every file inside it, so
  `core/` and everything under it were one teal ball. A silhouette reads at any
  distance; a size difference does not.
- **A folder is sized by what it CONTAINS**, not by its degree. By degree,
  `core/` with four subdirectories drew smaller than a leaf file imported five
  times — the opposite of what the tree means.
- **Containment edges lengthen with subtree size**, so a large branch occupies
  space proportional to its contents instead of folding in on itself.
- **Directory names are drawn in the scene** — region roots always, plus the 16
  largest directories. Capped by count rather than by a size threshold: a
  threshold is workspace-shaped, and on a workspace with a hundred similar
  skill directories every one cleared it at once and the region disappeared
  under overlapping text.

## 🧲 Categories occupy separate regions

Out of the box this graph had no clustering at all. The library's defaults are a
link force, unbounded repulsion, and `forceCenter` — which only translates the
whole point cloud and cannot hold anything in place.

- Each category is anchored to a fixed point on a Fibonacci sphere, with the
  workspace root pinned at the origin. Slots are allocated by index over a
  **fixed** lattice, so a region never moves when a filter empties another one.
- The anchor holds a region's own root hard and everything below it barely at
  all — pulling every folder toward the same point does not arrange a directory
  tree, it collapses one.
- Repulsion has a finite range. At the default `Infinity` every node pushes
  every other one and no clustering force can win against it.
- **Link stiffness is set per edge type**, because d3's default inverts the
  meaning we need: `1 / min(degree)` makes a similarity edge between two quiet
  documents roughly a hundred times stiffer than membership of a large
  directory. Containment is the skeleton; it has to dominate.

Measured live: region centroids ~880 units from the origin at an anchor radius
of 900, nearest pair 785 apart, cluster spreads 108–376.

## 🎯 Selecting something shows where it leads

- Focusing a node lights up its **whole branch** — every folder up to the
  workspace root and everything contained below it — plus what it imports or
  references. One hop lit the folder above and the children below and stopped,
  which says nothing about where a file sits or what a directory holds.
- A **breadcrumb** spells the path out: `Kyrei › Memory › .kyrei › handoff ›
  handoff_….md`.
- The camera frames the branch. The fixed 120-unit pull-back it replaces was
  calibrated when nodes were under a pixel; with folders 30 units across it put
  the camera *inside* the cluster.
- Filtering by category keeps the **scaffolding on the path** to whatever
  survived, so results still show where they came from — and nothing else:
  filtering to Sessions no longer leaves the code tree standing empty beside it.
- The sidebar source list is now the map's **colour key**; health moved to the
  ring around each swatch. Before, the dot encoded only health, so the view had
  no colour key at all.

## 🔭 Three framing bugs found only by measuring

- **`zoomToFit` lands twice too far.** Its distance formula applies `Math.atan`
  to the full field of view where the projection needs `Math.tan` of half of
  it. Measured: the camera 4 028 units from a graph 1 976 across, filling 40% of
  the width. The distance is now computed directly — **40% → 80%**.
- **Re-fitting only watched for growth.** A graph both expands and contracts:
  the library seeds nodes over a sphere sized by node count, and the category
  anchors then pull the whole thing inward. The band is now symmetric.
- **Labels scaled in world units swallowed the screen.** A 46-unit plate at 300
  units away covers half the view. Sprites now hold a constant fraction of the
  viewport.

## 🧹 Also

- `d3-force-3d` and `three` are declared dependencies instead of being imported
  transitively through `react-force-graph-3d`.
- The node-kind and edge-type tables agree with the tree about which category a
  node belongs to. They disagreed: every memory-derived `document` claimed
  `sourceId: "memory"` while living under the Documents root, so no node
  anywhere carried the `documents` id its own edges referenced.
- 22 new tests cover the layout maths, the containment derivation, the edge
  budget, alias resolution and the cache signature — the parts that can be
  tested without a GPU, which is why they were extracted from the canvas.

## 📌 Known, and deliberately not fixed here

- A region is still one cluster internally. Category is the only grouping
  principle, so the 1 449-node Skills region remains a ball. Community
  detection *inside* a region is the next step.
- On this workspace every `document` node is a skill-linked reference stub, so
  the Documents region is empty and Skills holds 58% of the graph.
