# Kyrei v0.7.15 — 🔬 the agent can now be measured, and it stopped forgetting the rules

v0.7.14 made the Memory Atlas legible. This release is about the layer under it:
what the agent actually knows about the project, what it remembers being told,
and — for the first time — a way to tell whether any of it is working.

Four research swarms were run against the current state of the art in agent
memory, context management, self-improvement and harness design. The most useful
thing they returned was **negative**: several things worth building turned out
to be refuted, and several things already built turned out to be unmeasured.
Both are recorded below.

## 🔌 The agent was blind to 40% of its own dependency graph

TypeScript under `"module": "NodeNext"` requires the **emitted** extension in the
import: `from "../data/ports.js"` while the file on disk is `ports.ts`. The
resolver tried `ports.js`, `ports.js.ts`, `ports.js/index.ts` — and never
`ports.ts`.

Measured on this repository: **794 of 796** relative `.js` specifiers were
unresolvable, and `core/engine` — 269 files, the largest directory in the
project — had **four** import edges in total.

- Import edges: **776 → 1445**. `core/engine`: **4 → 667**. Isolated files:
  433 → 240. Together with the alias fix in v0.7.14 the graph went **290 → 1445**,
  a fivefold increase in what `project_impact` can reason over.
- The `.js` fallback is tried **only after** the literal path fails, so a
  workspace that genuinely ships a `.js` beside a `.ts` still resolves where it
  asked.
- `EXTRACTOR_VERSION` bumped, so the incremental cache re-parses instead of
  serving edges the old rules produced — the invalidation mechanism added in
  v0.7.14, doing exactly the job it was added for.

## 🧷 Constraints stopped dying in compaction

A rule the user states once — "never run migrations against prod" — survived
**exactly one** compaction cycle and was gone by the second. Measured over six
cycles as `[true, false, false, false, false]`.

The flattening that causes this is deliberate: it stops the rolling summary
nesting into itself without bound. But a forgotten *task* gets re-asked, while a
forgotten *prohibition* gets violated, and this agent writes files and runs
commands. Published measurement of the same failure: 0% policy violations with
the constraint visible, **30% after compaction** (59% on some models), and
conditioned on survival — 0% if the constraint survived summarisation, 38% if it
was dropped.

Standing constraints are now carried by an explicit parse of their own section,
emitted ahead of the rolling summary so the next flatten cannot double them, and
capped separately so a verbose recent turn cannot squeeze them out.

**Extraction runs on user turns only.** Lifting a "you must always…" sentence out
of fetched page content into a section the model reads as standing policy is a
prompt-injection path; there is a test for it.

## 📐 Patch application is measured

`harness-metrics` tracked fifteen counters — turns, prunes, waste ratio,
post-edit verification — and **not one** apply outcome. The most failure-prone
surface in the harness had no signal at all, which made every downstream
question a guess: which patch grammar suits which provider, how far anchor
tolerance should stretch, whether a rejected hunk deserves an automatic retry.

`applyPatch` now reports the loosest anchor-match level any hunk needed (0 exact
→ 3 Unicode fold) and the tool layer feeds successes and `ApplyError` codes into
the snapshot. A rising match level is the early warning that a model's context
lines are drifting; previously the only signal was an outright failure.

## 🔬 An eval suite that can actually fail

The suite was three tasks and could not answer whether anything got better. It
is now **18 tasks across six capability categories** — editing, rejection,
safety, project intelligence, search, recovery.

**The selection rule is that a real defect got through.** Every task carries a
`rationale` naming that defect, and a test asserts the rationale is present.
Tasks invented to look thorough measure nothing.

Public benchmarks are deliberately **not** the gate: an audit of 168 of them
found problems in over a quarter of tasks, and on SWE-bench a model identifies
the buggy file from the issue text alone **76%** of the time versus **53%** off
benchmark — partly a memory test rather than a capability test.

### 🦷 Proven to have teeth

A passing suite proves nothing until it is shown to fail. The NodeNext
resolution fallback was removed and the suite re-run: `intel-nodenext-js-specifier`
went red and **every other task stayed green**. The catch is targeted, not a
blanket failure. The procedure is written into `report.md` to be repeated for
each new task.

### 🪤 It immediately caught two defects in its own oracles

- **"Nothing happened" is not evidence a guard fired.** The path-jail tasks
  asserted only that no file appeared outside the workspace — which a tool that
  silently did nothing, or was never called, satisfies equally well. Oracles now
  receive the run's tool outputs and must see the refusal *reported*.
- **A denial is not an exception.** The tools return jail denials as ordinary
  results so the model can recover from them, so the tool-error count stays at
  zero; asserting on it asserted the wrong thing. Separately,
  `search-grep-finds-match` was calling `grep_search` with the wrong parameter
  name and erroring on every single run — invisible, because its oracle checked
  the seed file, which was of course still there.

Edit oracles are now byte-exact rather than substring: "contains LINE2X" also
passes on a file the edit mangled everywhere else.

### 🚧 The regression gate got two new ways to fail

- a drop in **any category's** pass rate — the overall number holds steady if
  safety regresses while editing improves;
- a category **disappearing** from the run — deleting the safety tasks would
  otherwise be indistinguishable from passing them.

### 📏 What it measures, stated plainly

The model's decisions are **scripted**, so this tests the *harness* — tools,
patch application, the path jail, the index, the stream bridge — not the model's
judgement. That is worth measuring: with the model held fixed, harness choice
has been measured to move end-to-end pass rate by **27 percentage points**. And
it makes the suite deterministic, where model-in-the-loop pass rates vary **2–6
points even at temperature 0**.

What it cannot tell you is whether the agent chose the right action. That needs
a live-model arm — a separate and far noisier instrument.

## 🐛 Also

- `gateway-codex-thread-reset` raced: it waited on `turns.length`, which the
  connector pushes while the run is still in flight, so the second prompt could
  hit `session_busy` under a loaded parallel suite. It failed in the full run and
  passed in isolation — and it is what intermittently broke the gate before the
  v0.7.14 release, which was written off as flakiness at the time. It now waits
  on the persisted thread id, the completion signal its sibling test already
  used.

## 🧭 What the research said not to build

Recorded so it is not rediscovered later:

- **Retrieving past trajectories** for a coding agent measured **+0.0 points at
  +24% token cost**. Naive summarisation measured **−4**. Summary *quality* is
  the whole ballgame, not the retrieval plumbing.
- **Parallel writing sub-agents for code.** The strongest published multi-agent
  result comes with its own authors noting coding parallelises poorly and agents
  coordinate badly in real time. Kyrei's read-only-children design is the
  defensible position, not a deficiency.
- **LLM confidence scoring as a poisoning defence** is refuted: of 82 entries a
  trust-scoring judge admitted, 54 were malicious and scored a perfect 1.0.
- **Bi-temporal belief revision** buys audit, not accuracy: 36.27 vs 36.77 F1
  against plain last-write-wins.

One widely-quoted statistic turned out to be **fabricated** — a "decay
outperforms fixed TTL by 40%" figure attributed to a paper that does not contain
it, produced by a summariser against an unextractable PDF. Flagged here so it
does not propagate.

## 📌 Known, and deliberately not fixed here

- **Evolution promotion is unmeasured.** The evaluator is a single model call
  scoring its own confidence at a 0.5 threshold — its own comment says "no
  baseline and no replay, so the score is the only signal" — and the canary
  transition *is* the application, with no measurement window and no automatic
  rollback. Both now have somewhere to be measured; neither is fixed yet.
- **Automatic recall is BM25-only** and does not consult the vector store the
  project already ships, nor the sufficiency gate the explicit memory tools use.
- **The Atlas has no tool surface.** The agent builds the graph and never
  queries it.
